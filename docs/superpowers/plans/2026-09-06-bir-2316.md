# BIR Form 2316 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce BIR Form 2316 PDFs — the annual Certificate of Compensation Payment and Tax Withheld — for a calendar year, per employee or for everyone.

**Architecture:** Four stable identity fields added to `Employee` and `Company`; a `Bir2316Service` that aggregates an employee's paid runs for a year; the ported `Bir2316Document`; four HR-only endpoints; and a Blazor page to preview, complete and download.

**Tech Stack:** .NET 10 · QuestPDF · EF Core 10 + Npgsql · Blazor WebAssembly · xUnit · Moq · FluentAssertions

**Design spec:** [`docs/superpowers/specs/2026-09-06-bir-2316-design.md`](../specs/2026-09-06-bir-2316-design.md)

**Source of the port:** `C:\M2NET PROJECTS\payzen` (read-only; never modify it)

## Global Constraints

- Target framework `net10.0`.
- **Do not modify the byte-verified statutory files or their tests:** `PayrollComputationService.cs`, `PayrollLineBuilder.cs`, `DolePremiumRates.cs`, `BirWithholdingTax.cs`, `SssContributionSchedule.cs`, and `PayrollComputationServiceTests`, `PayrollLineBuilderTests`, `DolePremiumRatesTests`, `BirWithholdingTaxTests`. `git diff --stat` must never list them - **except `BirWithholdingTaxTests`, whose one expected change is Task 3 Step 1 below, restoring the five deferred Form 2316 facts.** That restoration is not a violation of this constraint; a later reader diffing `BirWithholdingTaxTests` against this line should expect exactly that change and nothing else, not chase it as a phantom breach.
- **Income is attributed by `PayDate.Year`, never `PeriodStart.Year`.** BIR taxes compensation in the year it is paid, and a December-into-January period is ordinary in a semi-monthly cycle.
- **Only runs with `Status == Paid` count.** A computed-but-unapproved run is not income, and `ComputeAsync` resets a run to `Draft` on every recompute.
- **Generation recomputes every derived figure server-side.** The request body supplies only fields a human legitimately provides. A tax certificate's money comes from payroll records, never from the caller.
- **Item 24 (tax due) is computed from Item 23 via `BirWithholdingTax.ComputeAnnualTaxDue`, never summed from withheld tax.** Their agreement is what qualifies an employee for substituted filing; conflating them destroys the only signal the form carries.
- All four endpoints require `Admin`, `HRManager` or `PayrollService`. There is no self-service equivalent.
- New DTO and type names follow PeopleCore casing: `Bir2316Dto`, not `BIR2316Dto`.
- The suite reports **235 passing** at the start of this plan.

```csharp
namespace PeopleCore.Domain.Payroll;

/// <summary>
/// Statutory caps that change by legislation rather than by company policy, so they live beside
/// the tax tables rather than in configuration.
/// </summary>
public static class StatutoryCaps
{
    /// <summary>
    /// Thirteenth-month pay and other benefits are exempt up to this amount per year
    /// (TRAIN, RA 10963). Anything above it is taxable compensation and lands in Item 48.
    /// </summary>
    public const decimal ThirteenthMonthExemption = 90_000m;
}
```

PayZen keeps this as a `const` inside `BIR2316Controller`. It belongs beside `BirWithholdingTax` and `SssContributionSchedule`: it is the same kind of fact, and when legislation moves it, it must move in one place.

### Task 4: Endpoints and the page

- [ ] **Step 1: The controller**

`[Route("api/reports/2316")]`, class-level `[Authorize(Roles = "Admin,HRManager,PayrollService")]` — unlike `ReportsController`, there is no self-service action here, so a class-level attribute is correct.

| Action | Route | Returns |
|---|---|---|
| `GetYears` | `GET years/{employeeId:guid}` | `IReadOnlyList<int>` |
| `GetPreview` | `GET preview/{employeeId:guid}?year=` | `Bir2316Dto`, 404 when null |
| `Generate` | `POST generate/{employeeId:guid}?year=` | the PDF |
| `GenerateAll` | `POST generate-all?year=` | every employee's, merged |

`Generate` takes `[FromBody] Bir2316ManualInputs` — **not** a full `Bir2316Dto`. The type is the enforcement: there is no field on it that could carry a derived figure, so the endpoint cannot be made to render caller-supplied money even by mistake. Add a comment saying so.

## Phase exit criteria

1. A 2316 PDF generates for an employee and a year, from the browser.
2. Its figures match the sum of that employee's paid runs for the year, attributed by pay date.
3. A derived figure cannot be supplied by the caller — enforced by the request type, asserted by test.
4. A run paid in January counts in January's year, not the prior December's, asserted by test.
5. Item 24 is computed from Item 23, asserted by the five restored tests.
6. `dotnet build` is clean, the suite is green, and no `RZ10012` appears.
7. The byte-verified statutory files and their tests are unchanged.

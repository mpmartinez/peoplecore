# BIR Form 2316 — Exact Official Form Output: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce output that *is* the official BIR Form 2316 — the Bureau's own PDF with values stamped onto it — replacing the hand-drawn QuestPDF reproduction.

**Architecture:** The blank official form and a TTF are embedded in `PeopleCore.Reports`. `Bir2316Stamper` opens the form with PDFsharp, draws values at coordinates held in `Bir2316FieldMap`, and returns bytes. `IBir2316Renderer` keeps its signature, so nothing above it changes.

**Tech Stack:** .NET 10 · PDFsharp 6.2.4 · xUnit · FluentAssertions

**Design spec:** [`docs/superpowers/specs/2026-09-06-bir-2316-exact-form-design.md`](../specs/2026-09-06-bir-2316-exact-form-design.md)

**The official form:** `C:\Users\mpmar\Downloads\2316 Sep 2021 ENCS_Final_corrected (1).pdf` — 612 × 936 pts, single page, no AcroForm fields.

- [ ] **Step 2: Write the font resolver**

PDFsharp has no default font resolver and throws `InvalidOperationException: No appropriate font found` without one. The spike used `FailsafeFontResolver`, which substitutes silently — fine for a spike, wrong for output that must look the same everywhere.

Implement `PdfSharp.Fonts.IFontResolver` reading the embedded TTFs, so a Linux container renders what a Windows machine does. Assign it once via `GlobalFontSettings.FontResolver`, guarded so repeated assignment is harmless — the stamper may be constructed per request.

- [ ] **Step 3: Write the failing test**

```csharp
[Fact]
public void Stamp_ProducesTheOfficialPageSize()
{
    var pdf = new Bir2316Stamper().Stamp(SampleDto());

    using var doc = PdfReader.Open(new MemoryStream(pdf), PdfDocumentOpenMode.ReadOnly);
    doc.PageCount.Should().Be(1);
    // 612 x 936 pts = 8.5 x 13in, Philippine folio. The QuestPDF version used Legal
    // (8.5 x 14in) and was a full inch too tall, so nothing aligned on official stock.
    doc.Pages[0].Width.Point.Should().BeApproximately(612, 0.5);
    doc.Pages[0].Height.Point.Should().BeApproximately(936, 0.5);
}

[Fact]
public void Stamp_IsDeterministic()
{
    var dto = SampleDto();
    var a = new Bir2316Stamper().Stamp(dto);
    var b = new Bir2316Stamper().Stamp(dto);

    // Font resolution must not depend on the machine. If this fails, the resolver is
    // falling back to a system font rather than the embedded one.
    a.Should().Equal(b);
}
```

If `Stamp_IsDeterministic` fails because PDFsharp writes a creation timestamp into the document, set the document's `Info.CreationDate` to a fixed value and say so in your report — the point is that the *rendering* is deterministic, not that PDFsharp never varies a byte.

### Task 2: The coordinate map

**Files:**
- Create: `src/PeopleCore.Reports/Bir2316FieldMap.cs`
- Modify: `src/PeopleCore.Reports/Bir2316Stamper.cs`
- Test: extend `Bir2316StamperTests`

**Interfaces:**
- Produces: `Bir2316FieldMap` — a static table of field → `(double X, double Y, FieldAlign Align)`

- [ ] **Step 1: Derive the label coordinates**

Do not guess. The blank form's printed labels give you the geometry. Run this against the official PDF and keep the output as your reference — put it in your report:

```bash
python - <<'PYEOF'
import pypdf
r = pypdf.PdfReader(r"C:\Users\mpmar\Downloads\2316 Sep 2021 ENCS_Final_corrected (1).pdf")
runs, last = [], (0.0, 0.0)
def visit(text, cm, tm, font, size):
    global last
    t = text.strip()
    x, y = round(tm[4], 1), round(tm[5], 1)
    if x or y:
        last = (x, y)
    if t:
        runs.append((last[0], last[1], t))
r.pages[0].extract_text(visitor_text=visit)
for x, y, t in sorted(runs, key=lambda v: (-v[1], v[0])):
    print(f"{x:7.1f} {y:7.1f}  {t}")
PYEOF
```

Note the visitor reports `(0, 0)` for continuation runs where the text matrix was not reset; the snippet carries the last real position forward, which is why it is written this way.

A value's position derives from its label: same baseline for a value on the same line, or the line below for a boxed field. **Amount columns are right-aligned on the official form** — record an alignment per field, and right-align money against the column's right edge rather than left-aligning it and hoping.

- [ ] **Step 2: Write the map**

One entry per field the service populates. Record, in a comment on each, the label it was measured from — so the next person can re-derive it rather than trusting a magic number:

```csharp
/// <summary>
/// Where each value lands on the September 2021 ENCS form, in PDF points, origin bottom-left on
/// the 612 x 936 page. Derived from the blank form's own printed labels rather than guessed; each
/// entry records the label it was measured against so it can be re-derived when BIR revises the
/// form.
/// </summary>
internal static class Bir2316FieldMap
{
    internal enum Align { Left, Right }
    internal readonly record struct Field(double X, double Y, Align Align = Align.Left);

    // "3 TIN" label at x=39.8 y=807.2 - value sits on the same baseline, right of the caption.
    internal static readonly Field EmployeeTin = new(95, 807);
    // ...
}
```

- [ ] **Step 3: Stamp every field**

Extend the stamper to walk the map. Money formats with thousands separators and two decimals, matching how the figures read on a payslip. An empty or zero value for an optional box prints nothing — the official form leaves unused boxes blank, and a page of `0.00` is harder to read and implies a figure was computed when it was not.

# Payslips — Phase 4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce payslip PDFs — downloadable by HR for one employee or a whole run, and by an employee for their own.

**Architecture:** A new `PeopleCore.Reports` project carrying the ported QuestPDF `PayslipDocument`, a reports controller with two HR endpoints and one self-service endpoint, and download actions on the register plus an ESS page.

**Tech Stack:** .NET 10 · QuestPDF · Blazor WebAssembly · xUnit · Moq · FluentAssertions

**Design spec:** [`docs/superpowers/specs/2026-09-06-payslips-design.md`](../specs/2026-09-06-payslips-design.md)

**Source of the port:** `C:\M2NET PROJECTS\payzen` (read-only; never modify it)

## Global Constraints

- Target framework `net10.0`.
- **Do not modify the Phase 1 statutory files or their tests:** `PayrollComputationService.cs`, `PayrollLineBuilder.cs`, `DolePremiumRates.cs`, `BirWithholdingTax.cs`, `SssContributionSchedule.cs`, and `PayrollComputationServiceTests`, `PayrollLineBuilderTests`, `DolePremiumRatesTests`, `BirWithholdingTaxTests`. `git diff --stat` must never list them.
- **The ESS endpoint takes no employee id.** It resolves the caller from `ICurrentUserService.EmployeeId`, never from a route parameter. A route parameter is user input, and a payslip is the most personal document this system produces.
- HR endpoints carry `[Authorize(Roles = "Admin,HRManager,PayrollService")]`. The ESS endpoint carries a bare `[Authorize]` — any authenticated employee may fetch their own.
- `QuestPDF.Settings.License` is set **once at startup**, never per action.
- BIR 2316 is out of scope entirely — do not port `BIR2316Document`, `BIR2316Dto`, or `BIR2316Controller`.
- This repository has no Blazor component tests and this phase does not add them. Pages are verified in a browser.
- The suite reports **208 passing** at the start of this plan.

### Task 2: The payslip service

**Files:**
- Create: `src/PeopleCore.Application/Payroll/Interfaces/IPayslipService.cs`, `src/PeopleCore.Application/Payroll/Services/PayslipService.cs`
- Test: `tests/PeopleCore.Application.Tests/Payroll/PayslipServiceTests.cs`

**Interfaces:**
- Consumes: `IPayrollRunRepository.GetWithEntriesAsync`, a company source, `PayslipDocument`
- Produces:

```csharp
public interface IPayslipService
{
    /// <summary>One employee's payslip, or null when the run or the entry does not exist.</summary>
    Task<byte[]?> GenerateAsync(Guid runId, Guid employeeId, CancellationToken ct = default);

    /// <summary>Every payslip in the run merged into one PDF, or null when the run does not exist.</summary>
    Task<byte[]?> GenerateForRunAsync(Guid runId, CancellationToken ct = default);
}
```

**The layering, concretely.** `PeopleCore.Reports` references `PeopleCore.Application`, so `PayslipService` — which lives in Application — cannot reference `PayslipDocument` directly without a project cycle. Break it with a renderer interface, exactly the shape `IStorageService` uses (declared in `Application/Common/Interfaces`, implemented in `Infrastructure/Storage`):

```csharp
// src/PeopleCore.Application/Payroll/Interfaces/IPayslipRenderer.cs
namespace PeopleCore.Application.Payroll.Interfaces;

/// <summary>
/// Renders payslip PDFs. Implemented in PeopleCore.Reports, which references Application - so
/// Application declares the contract and never names QuestPDF, keeping the dependency pointing
/// inward.
/// </summary>
public interface IPayslipRenderer
{
    byte[] Render(PayrollRunDto run, PayrollRunEmployeeDto employee, PayslipCompanyDto company);

    /// <summary>Every entry merged into one document, in the order given.</summary>
    byte[] RenderMerged(PayrollRunDto run, IReadOnlyList<PayrollRunEmployeeDto> employees, PayslipCompanyDto company);
}
```

`PayslipService` (Application) assembles the DTOs and calls `IPayslipRenderer`. `PayslipRenderer` (Reports) is a thin wrapper that constructs `PayslipDocument` and calls `GeneratePdf()` / `Document.Merge(...)`. Register it in `ServiceExtensions`. Mock `IPayslipRenderer` in `PayslipServiceTests` so the service tests assert assembly and lookup behaviour without generating PDFs — `PayslipDocumentTests` already covers rendering.

- [ ] **Step 1: Set the QuestPDF licence once, at startup**

In `Program.cs`, near the other startup configuration:

```csharp

// actions; three copies of a global setting is three places to forget one, and the failure
// surfaces at PDF generation rather than at start-up.
QuestPDF.Settings.License = QuestPDF.Infrastructure.LicenseType.Community;
```

- [ ] **Step 2: Write the controller**

```csharp
[ApiController]
[Route("api/reports")]
public class ReportsController : ControllerBase
```

Three actions, following the shape of the other payroll controllers:

- `GET payslip/{runId:guid}/{employeeId:guid}` — `[Authorize(Roles = "Admin,HRManager,PayrollService")]`. 404 when the service returns null. Otherwise `File(bytes, "application/pdf", filename)`.
- `GET payslips/{runId:guid}` — same roles, the merged run PDF.
- `GET my-payslip/{runId:guid}` — **a bare `[Authorize]`**, and **NO employee id in the route**.
- `GET my-payslips` — **a bare `[Authorize]`**, also taking no employee id. Returns the runs the caller appears in, so the ESS page has something to list: for each, the run id, run number, period label, pay date and the caller's own net pay. It resolves the caller identically and returns 403 without an `employee_id` claim. Add a service method alongside `GenerateAsync` for it, and a DTO — `MyPayslipSummaryDto(Guid RunId, string RunNumber, string PeriodLabel, DateOnly PayDate, decimal NetPay)`. It must return only rows for the caller's own employee id; returning another employee's net pay here would leak compensation just as surely as serving their PDF.

The self-service action resolves the caller:

```csharp
        var employeeId = _currentUser.EmployeeId;
        if (employeeId is null)
            return Forbid();

        var pdf = await _payslips.GenerateAsync(runId, employeeId.Value, ct);
```

Inject `ICurrentUserService`. **Never accept an employee id from the caller on this route.** A route parameter is user input; taking one here would let any authenticated employee read anyone's payslip by editing a GUID. Add a comment saying exactly that, because the next person to add a feature here will be tempted to parameterise it.

Register `IPayslipService` in `ServiceExtensions.AddInfrastructure`'s existing `// Payroll` block.

- [ ] **Step 3: Write the authorization tests**

These are the phase's most important tests. Full bodies:

```csharp
using System.Reflection;
using FluentAssertions;
using Microsoft.AspNetCore.Authorization;
using PeopleCore.API.Controllers.Payroll;

namespace PeopleCore.Application.Tests.Payroll;

public class PayslipAuthorizationTests
{
    private static MethodInfo Action(string name) =>
        typeof(ReportsController).GetMethod(name, BindingFlags.Public | BindingFlags.Instance)
            ?? throw new InvalidOperationException($"ReportsController has no public action '{name}'.");

    [Theory]
    [InlineData("GetMyPayslip")]
    [InlineData("GetMyPayslips")]
    public void SelfServiceActions_AcceptNoEmployeeId(string actionName)
    {
        // The route cannot be made to serve someone else's payslip because it has nowhere to
        // put an employee id. The caller is resolved from the employee_id claim instead.
        var parameters = Action(actionName).GetParameters().Select(p => p.Name!.ToLowerInvariant());

        parameters.Should().NotContain(p => p.Contains("employee"));
    }

    [Theory]
    [InlineData("GetPayslip")]
    [InlineData("GetRunPayslips")]
    public void HrActions_AdmitOnlyPayrollRoles(string actionName)
    {
        var attribute = Action(actionName).GetCustomAttribute<AuthorizeAttribute>();

        attribute.Should().NotBeNull("HR payslip actions must be role-restricted");
        attribute!.Roles!.Split(',', StringSplitOptions.TrimEntries)
            .Should().BeEquivalentTo(["Admin", "HRManager", "PayrollService"]);
    }
}
```

Name the controller's actions to match those strings, or adjust the strings to the names you chose — but keep the assertions. The test project already references `PeopleCore.API` (added in Phase 1 for `CompensationAuthorizationTests`), whose reflection style this follows.

## Phase exit criteria

1. HR can download one employee's payslip and a merged PDF of a whole run, from the register.
2. An employee can download their own payslip from ESS.
3. The self-service route accepts no employee id, asserted by test — another employee's payslip is unreachable by any route parameter.
4. `QuestPDF.Settings.License` is set once at startup and nowhere else.
5. `dotnet build` is clean, the suite is green, and no `RZ10012` warning appears.
6. The Phase 1 statutory files and their tests are byte-unchanged.
